# Feature Specification: Material Design 3 界面视觉升级

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: Implemented

**Input**: User description: "spec kit https://m3.material.io UI风格参考这个"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以 Material 3 风格管理容器 (Priority: P1)

本机用户进入 Container GUI 后，可以在统一、清晰的 Material 3 视觉体系中查看容器状态、资源指标、详情和操作，不必重新学习已有功能的位置。

**Why this priority**: 主仪表板是所有管理任务的入口；视觉升级必须先改善信息层级，同时保证原有任务路径不变。

**Independent Test**: 在桌面宽度打开首页，确认顶部栏、状态区、统计卡、容器列表、详情面板和操作按钮采用一致的语义色彩、形状、排版与层级，并且所有原有入口仍可识别和使用。

**Acceptance Scenarios**:

1. **Given** 用户打开已加载数据的仪表板，**When** 查看整个页面，**Then** 页面以一致的表面层级、圆角、类型比例和间距区分顶部栏、统计、主列表与详情。
2. **Given** 页面同时存在主要、次要、危险和不可用操作，**When** 用户查看操作区，**Then** 每类操作的强调程度和状态都能通过颜色、容器形状及文字清楚辨认。
3. **Given** 容器处于运行、停止、读取中或失败状态，**When** 页面刷新状态，**Then** 状态使用语义化标签和文字表达，不能只依赖颜色。

---

### User Story 2 - 在表格、表单与弹窗中获得一致反馈 (Priority: P2)

用户搜索镜像、创建容器、拉取镜像或确认危险操作时，可以在一致的 Material 3 控件中获得清晰的悬停、焦点、按下、禁用、错误和进度反馈。

**Why this priority**: 这些流程包含数据输入和有风险的变更；一致状态可降低误操作并提升键盘使用体验。

**Independent Test**: 仅使用键盘遍历搜索、按钮、折叠箭头和弹窗表单，确认焦点始终可见；再检查错误、禁用、进度和危险确认状态均有独立视觉表达。

**Acceptance Scenarios**:

1. **Given** 用户使用键盘操作页面，**When** 焦点经过可交互元素，**Then** 每个元素都有清晰且不被裁切的可见焦点。
2. **Given** 用户打开创建、拉取或确认弹窗，**When** 弹窗显示，**Then** 背景遮罩、弹窗表面、标题、字段和操作区形成清楚的模态层级。
3. **Given** 操作正在执行、失败或暂不可用，**When** 相应状态出现，**Then** 控件和状态消息在浅色与深色主题下均保持可读且不会造成成功误判。

---

### User Story 3 - 在不同窗口和系统主题下保持可用 (Priority: P3)

用户在桌面、较窄窗口以及系统浅色或深色主题下使用 Container GUI 时，仍能看到完整的任务层级和可操作内容。

**Why this priority**: 该工具主要用于桌面浏览器，但用户会改变窗口大小和系统主题；视觉升级不能只在单一截图尺寸成立。

**Independent Test**: 分别在扩展、紧凑宽度及浅色、深色主题下读取页面，确认布局自适应、文字和状态可读、表格可滚动，且不存在横向页面溢出。

**Acceptance Scenarios**:

1. **Given** 窗口宽度缩小至紧凑布局，**When** 用户浏览仪表板，**Then** 主列表与详情按单列排列，操作区不会遮挡或溢出视口。
2. **Given** 系统切换浅色或深色主题，**When** 页面重新计算样式，**Then** 所有表面、文字、边界、焦点与状态使用对应语义角色并保持清晰。
3. **Given** 用户启用减少动态效果偏好，**When** 页面出现折叠、悬停或状态变化，**Then** 非必要动画被移除或显著缩短。

### Edge Cases

- 容器名称、镜像引用、错误消息或中文说明很长时，内容必须换行或截断在所属表面内，不得破坏整体布局。
- 表格列数超过窄窗口可容纳范围时，只允许表格区域横向滚动，不得让整个页面横向溢出。
- 浏览器不支持部分现代颜色函数或背景模糊时，基础颜色、边界和层级仍必须可用。
- 页面处于首次加载、空列表、CLI 不可用、局部失败或执行进度中时，状态仍必须符合统一视觉层级。
- 系统图标、字体或网络不可用时，页面不得依赖外部 CDN 才能显示关键文字和操作。
- 破坏性操作必须继续通过现有确认流程，视觉变化不得削弱红色危险语义或二次确认。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 页面 MUST 采用 Material 3 语义色彩角色组织主要、次要、表面、轮廓、错误及其对应前景色，而不是在组件中散落无语义颜色。
- **FR-002**: 页面 MUST 为浅色和深色主题提供完整且配对的语义色彩，系统主题切换后不得丢失文字、边界或状态对比。
- **FR-003**: 页面 MUST 使用统一的显示、标题、正文和标签类型层级，关键标题和操作可适度强调，密集表格仍以可读性为先。
- **FR-004**: 顶部栏、状态卡、统计卡、资源面板、详情面板、表格、日志和弹窗 MUST 使用一致的 Material 3 表面、圆角和有限层级。
- **FR-005**: 主要、次要、危险、小型与图标按钮 MUST 具有可辨认的启用、悬停、焦点、按下和禁用状态，并维持现有操作语义。
- **FR-006**: 输入框、下拉框、文本区域、复选框、搜索控件和字段错误 MUST 形成一致的字段样式与键盘焦点反馈。
- **FR-007**: 运行、停止、健康、警告、错误、读取中和操作进度 MUST 同时使用文字与语义视觉提示，不得只依赖颜色传达。
- **FR-008**: 页面 MUST 保持容器列表与详情的支持面板布局，在中等及紧凑宽度自动切换为可读单列布局。
- **FR-009**: 表格 MUST 保持信息密度、可读表头、行状态反馈和局部滚动，不得删除现有字段或操作。
- **FR-010**: 弹窗 MUST 使用明确遮罩、独立表面、清晰标题和底部操作区，并保留现有表单校验及危险确认行为。
- **FR-011**: 页面 MUST 为所有键盘可交互元素提供可见焦点，并尊重系统减少动态效果偏好。
- **FR-012**: 视觉实现 MUST 自包含于现有静态资源，不得引入前端构建链、远程字体、远程图标或运行时 CDN 依赖。
- **FR-013**: 视觉升级 MUST 保留现有 DOM 标识、API 契约、中文文案、自动刷新、折叠箭头语义和全部安全控制流程。
- **FR-014**: 自动化验证 MUST 覆盖设计令牌、关键组件状态、自适应规则、主题规则和无外部依赖约束。
- **FR-015**: 应用版本 MUST 按向后兼容的新功能递增，并与本次规格、实现和验证在同一 Git 提交中交付。

### Key Entities

- **Material 3 设计令牌**: 可复用的语义色彩、类型、形状、间距、层级和动效决策，分别覆盖浅色与深色主题。
- **组件视觉状态**: 一个交互组件的启用、悬停、焦点、按下、禁用、选中、错误或执行中状态。
- **自适应布局状态**: 扩展、中等与紧凑窗口下的面板排列、操作区域和表格滚动方式。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首页、容器详情、本机镜像、远程搜索以及三个现有弹窗均使用同一套语义设计令牌，不再依赖各区域独立定义的主题颜色。
- **SC-002**: 100% 的可交互控件在键盘操作时有可见焦点，主要、次要、危险和禁用操作可在不阅读实现代码的情况下区分。
- **SC-003**: 在至少一个扩展宽度和一个紧凑宽度验收中，页面无整体横向溢出，详情与操作仍可读取和使用。
- **SC-004**: 浅色与深色主题各完成一次可见页面验收，所有关键正文、状态、轮廓和焦点均可辨认。
- **SC-005**: 现有前端行为测试和完整服务测试全部通过，容器、镜像及确认操作的行为契约不发生变化。
- **SC-006**: 页面关键视觉资源在断开外部网络时仍可加载，HTML 与 CSS 不包含远程字体、远程图标或 CDN 引用。

## Assumptions

- “参考 Material 3”解释为采用官方设计系统的原则与组件语言，而不是复制 Material 官网的内容、图片、商标或页面结构。
- 本次覆盖 Container GUI 的完整视觉系统；不增加新的容器管理能力，也不改变后端 API。
- 当前 M3 Expressive 强调更鲜明的色彩、灵活排版、对比形状与适应性；本工具采用克制版本，以桌面管理控制台的信息密度和可靠性为优先。
- 系统主题仍通过浏览器的浅色/深色偏好自动选择，本次不增加独立主题设置或持久化配置。
- 现有原生 HTML、CSS 和少量 JavaScript 足以完成改造，不引入 Material Web 或其他前端依赖。
