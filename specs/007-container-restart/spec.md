# Feature Specification: 容器重启

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: Implemented

**Input**: User description: "给容器添加重启"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 重启运行中的容器 (Priority: P1)

本机用户在容器详情中可以重启一个正在运行的容器，无需先手动停止再返回页面启动。

**Why this priority**: 重启是配置生效和故障恢复的高频操作，合并为一次明确操作可减少误操作并缩短处理时间。

**Independent Test**: 使用一个模拟的运行中容器确认重启，验证其依次经历停止和重新运行，并且最终详情状态为运行中。

**Acceptance Scenarios**:

1. **Given** 用户查看一个运行中的容器，**When** 点击“重启容器”并确认目标，**Then** 系统接受一次重启操作，暂时禁用同一容器的其他变更按钮，并展示可追踪的操作状态。
2. **Given** 重启的停止和启动步骤均成功，**When** 系统完成独立状态回读，**Then** 操作显示成功，容器详情和列表均显示运行中。
3. **Given** 用户查看一个已停止的容器，**When** 查看可用操作，**Then** 页面只提供现有的启动和删除操作，不显示重启操作。

---

### User Story 2 - 清楚处理重启失败 (Priority: P2)

本机用户在重启失败时能知道操作没有完成，并看到安全、简洁且可继续处理的错误信息。

**Why this priority**: 重启包含两个连续状态变化；错误地显示成功可能掩盖容器已经停止或尚未恢复的事实。

**Independent Test**: 分别模拟停止失败、停止后启动失败、状态被外部改变和重复提交，确认不会出现错误顺序、重复执行或虚假成功。

**Acceptance Scenarios**:

1. **Given** 容器停止步骤失败，**When** 执行重启，**Then** 系统不尝试启动，操作显示失败并回读当前状态。
2. **Given** 容器已正常停止但重新启动失败，**When** 执行重启，**Then** 操作显示失败，页面明确展示回读到的实际状态，不把“已停止”当作重启成功。
3. **Given** 同一容器已有控制操作进行中，**When** 用户再次提交重启或其他控制操作，**Then** 系统拒绝冲突请求且不会并行改变该容器。

### Edge Cases

- 提交前容器已被外部命令停止时，系统必须拒绝重启前置状态，不得把它隐式当作启动请求。
- 同一幂等键重复提交相同重启请求时，必须返回同一个操作；用于不同请求时必须拒绝。
- 停止成功但启动超时、非零退出或状态回读仍不是运行中时，整个重启必须失败。
- 容器在停止后消失时，系统必须停止流程并报告真实状态，不得继续猜测或创建同名容器。
- CLI 未运行、目标标识无效、输出无法解析或请求来源不合法时，必须沿用现有受控错误边界。
- 页面刷新不得自动重复重启；刷新后必须从 CLI 重新读取最终状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅为运行中的容器提供“重启容器”操作；已停止容器 MUST 保持现有启动和删除操作。
- **FR-002**: 重启前 MUST 展示容器目标并要求用户明确确认，页面刷新或操作重试 MUST NOT 自动重复提交。
- **FR-003**: 重启 MUST 表示容器从运行中正常停止，再从停止状态恢复到运行中，两个阶段顺序不得颠倒或并行。
- **FR-004**: 系统 MUST 在执行前确认容器仍在运行；前置状态不匹配时 MUST 拒绝，不能把重启降级为单独启动。
- **FR-005**: 停止阶段失败时系统 MUST NOT 尝试启动；启动阶段失败时整个重启 MUST 显示失败。
- **FR-006**: 重启只有在最终独立回读确认目标容器存在且处于运行中时才能显示成功。
- **FR-007**: 重启 MUST 使用现有的单目标操作互斥和幂等规则，防止同一容器并发执行启动、停止、重启或删除。
- **FR-008**: 操作记录 MUST 区分重启与单独启动或停止，并记录目标、开始和结束时间、最终状态以及可安全展示的失败摘要。
- **FR-009**: 重启进行期间页面 MUST 禁用该容器的变更按钮；完成后 MUST 刷新列表、详情和资源指标。
- **FR-010**: 重启实现 MUST NOT 使用批量、强制停止、删除、重建或任意命令输入。
- **FR-011**: 此功能 MUST 保持现有启动、正常停止、删除、日志、SSH 状态和详情读取行为兼容。
- **FR-012**: 自动化验证 MUST 使用可替换的命令适配器或浏览器安全模拟，不得通过测试重启用户的真实容器。

### Key Entities

- **重启操作**: 针对单一容器的受控异步操作，具有幂等键、进行状态、停止与启动阶段结果、最终状态回读和安全错误摘要。
- **容器状态回读**: 从当前 CLI 状态读取的容器存在性和运行状态，用于重启前置条件与完成判定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可从运行中容器详情在两次交互内提交一次重启，无需手动切换停止和启动操作。
- **SC-002**: 100% 的成功用例都具备“先停止、后启动、最终运行中”的可验证顺序和状态回读。
- **SC-003**: 100% 的停止失败、启动失败和最终状态不匹配用例都显示失败，且不会出现虚假成功。
- **SC-004**: 对同一容器的并发或重复请求在自动化验证中不会造成重复停止或重复启动。
- **SC-005**: 重启完成后的一个页面刷新周期内，列表和详情展示与实际容器状态一致。

## Assumptions

- “重启”仅适用于当前处于运行中的容器；停止状态继续使用已有“启动容器”。
- 重启采用与现有“正常停止”一致的温和停止语义，不引入强制停止选项。
- 重启会短暂中断容器服务，因此沿用需要用户确认的控制操作模式。
- 批量重启、定时重启、自动重启策略和修改容器配置不在本次范围内。

## Implementation Evidence

- 2026-08-30：目标契约测试验证重启接受、stop → start 顺序、幂等重放、确认与状态门禁、同目标互斥、两阶段失败短路以及状态回读不匹配。
- 2026-08-30：Swift 全量测试 161 项，2 项只读可选测试跳过，0 失败；Node 前端测试 4 项，0 失败；`git diff --check` 通过。
- 2026-08-30：运行态 API 回读 GUI `2.9.0` 与 Apple container `1.3.1`；错误确认的重启请求返回 `422 CONFIRMATION_MISMATCH`；浏览器确认运行中容器显示“重启容器”，确认框显示精确目标与中断提示，随后取消操作。
- 2026-08-30：浏览器验收后只读 CLI 回读 `postgres-odoo-apple`、`odoo19`、`Ubuntu26.04` 仍为运行中且启动时间未变化，未执行真实容器重启。
