# Feature Specification: 拉取镜像与创建容器

**Feature Branch**: `main`

**Created**: 2026-08-29

**Status**: Complete

**Input**: User description: "添加功能，需要能创建容器和拉取镜像"

## Clarifications

### Session 2026-08-29

- Q: 是否继续提供 GHCR 专用集成？ → A: 不提供；移除 GHCR 搜索、快捷选择和 GitHub Token 配置，但保留通用完整镜像地址拉取。
- Q: 你说的“直接展示全部镜像”，希望首页具体展示哪一类镜像？ → A: 首页立即展示全部本机镜像；Docker Hub 只在输入关键词后分页展示全部匹配结果。
- Q: 搜索到一个镜像仓库后，应该怎样选择具体版本标签？ → A: 点击仓库后分页展示全部可用标签，用户选择准确标签后填入拉取表单，不自动假定 `latest`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拉取容器镜像 (Priority: P1)

作为本机容器管理员，我希望在浏览器中输入镜像引用并拉取镜像，以便无需切换到终端即可准备
创建容器所需的镜像，并能看到操作进度和最终回读结果。

**Why this priority**: 镜像是创建容器的前置资源，单独完成该故事即可替代一项高频命令行操作。

**Independent Test**: 使用固定的成功、重复拉取、超时、非零退出和回读缺失样本提交镜像引用；可以
验证请求被校验、操作状态可轮询、成功结果包含权威镜像回读，且失败不影响现有容器管理功能。

**Acceptance Scenarios**:

1. **Given** 本机已有一个或多个镜像，**When** 用户打开镜像区域，**Then** 页面显示每个镜像的名称、
   摘要、平台和大小，并明确标出最新观测时间。
2. **Given** 一个格式有效且本机尚不存在的镜像引用，**When** 用户提交拉取，**Then** 页面立即显示
   可追踪的进行中操作，并在完成后显示镜像名称、摘要、平台和大小回读。
3. **Given** 一个本机已经存在的镜像引用，**When** 用户再次提交拉取，**Then** 操作可以安全完成，
   并以拉取后的实际镜像信息作为成功依据。
4. **Given** 用户选择了可选平台，**When** 提交拉取，**Then** 只对该请求使用所选平台，并在回读中
   验证存在相符平台。
5. **Given** 注册表不可达、认证失败、命令超时或返回非零结果，**When** 操作结束，**Then** 页面显示
   中文失败状态和安全错误摘要，不把请求已接受显示为拉取成功。
6. **Given** 镜像引用或平台格式无效，**When** 用户提交，**Then** 页面指出具体字段错误，且不执行
   任何镜像变更。
7. **Given** 用户选择 Docker Hub，**When** 输入仓库内的镜像路径并提交，**Then** 页面构造确定的
   `docker.io` 引用后再提交；其他 OCI 注册表通过“完整地址 / 自动识别”原样提交。
8. **Given** 用户搜索 Docker Hub，**When** 输入关键词并翻页，**Then** 页面通过服务端公开搜索显示
   匹配的公开仓库，并可把选中的完整引用带入拉取表单。
9. **Given** 用户首次打开页面且未执行远程搜索，**When** 本机镜像读取完成，**Then** 页面直接显示
    权威本机列表中的全部镜像，不自动请求 Docker Hub API。
10. **Given** 远程搜索返回一个镜像仓库，**When** 用户打开该仓库，**Then** 页面分页展示来源 API
    返回的可用标签；只有用户选择具体标签后，完整引用才填入拉取表单，且不会自动提交拉取。
11. **Given** 镜像拉取正在执行，**When** Apple Container CLI 输出下载或解压进度，**Then** 页面显示
    对应阶段和单调不倒退的总进度条；进入权威回读时显示验证阶段，完成前不得伪装为成功。
12. **Given** 本机镜像区域已加载，**When** 用户使用“本机镜像”标题旁的箭头收起或展开，**Then** 镜像内容
    相应隐藏或显示，箭头向右或向下，且 `aria-expanded` 与无障碍名称同步更新；后台刷新继续，提交拉取或创建时区域自动展开。

### User Story 2 - 创建容器 (Priority: P2)

作为本机容器管理员，我希望通过受控表单创建容器，以便配置常用的名称、镜像、资源限制、端口、
环境变量和启动参数，并可选择在创建完成后启动容器。

**Why this priority**: 创建容器是本需求的核心管理能力，但可以使用本机已有镜像独立验收，不依赖
用户故事 1 已完成。

**Independent Test**: 使用固定的容器列表与创建结果样本提交最小表单和完整表单；可以验证输入只会
生成允许的参数、创建后按名称回读容器、可选启动经过第二次状态回读，且秘密值不会出现在响应中。

**Acceptance Scenarios**:

1. **Given** 一个不存在的有效容器名称和可用镜像，**When** 用户提交最小创建表单，**Then** 系统创建
   容器但不自动启动，并在回读中确认该名称的容器处于已创建或已停止状态。
2. **Given** 用户填写 CPU、内存、一个或多个端口、环境变量和进程参数，**When** 提交创建，**Then**
   所有通过校验的设置只应用到目标容器，操作摘要不包含环境变量值。
3. **Given** 用户勾选创建后启动，**When** 创建回读成功，**Then** 系统再启动该容器，并以最终运行中
   状态回读作为整个操作成功的依据。
4. **Given** 同名容器已经存在或在提交后被其他进程创建，**When** 创建前校验或最终回读发生，**Then**
   操作以状态冲突失败，不覆盖、不删除也不复用现有容器。
5. **Given** 创建命令返回成功但目标容器未出现在权威列表中，**When** 验证阶段结束，**Then** 操作
   标记为失败并明确说明回读不匹配。
6. **Given** 名称、镜像、CPU、内存、端口、环境变量或进程参数不合法，**When** 用户提交，**Then**
   页面显示逐字段错误，且不执行创建或启动；主机端口低于 1024 时必须明确说明需要 root 权限。

### User Story 3 - 删除不需要的容器 (Priority: P1)

作为本机容器管理员，我希望在详情中删除已经停止或仅创建的容器，以便清理不再需要的容器，且不会
误删仍在运行的目标。

**Independent Test**: 使用固定容器列表和模拟命令执行器，验证精确确认、运行中拒绝、固定删除参数、
幂等操作及删除后的缺失回读；自动化不得删除真实容器。

**Acceptance Scenarios**:

1. **Given** 容器处于已停止或已创建状态，**When** 用户点击“删除容器”并确认页面展示的精确标识，
   **Then** 服务只执行 `container delete <id>`，随后重新读取列表，只有目标确实不存在时才显示成功。
2. **Given** 容器仍在运行，**When** 用户尝试删除，**Then** 页面不提供删除入口，服务端也以状态冲突
   拒绝直接请求，且不执行删除命令。
3. **Given** 确认目标与 URL 中的容器标识不完全相同，**When** 提交删除，**Then** 请求以确认不匹配
   拒绝，且不执行删除命令。
4. **Given** 删除命令退出为零但目标仍出现在最新列表，**When** 操作进入验证阶段，**Then** 操作失败，
   不把进程退出码当作删除成功。

### Edge Cases

- 镜像引用包含注册表端口、命名空间、标签或摘要时，必须作为单个不透明引用校验和传递，不能按
  空格或 shell 元字符拆分。
- Docker Hub 短名称 `postgres:latest` 解析为 `docker.io/library/postgres:latest`；带命名空间的名称
  解析为 `docker.io/<namespace>/<image>`；其他 OCI 注册表必须填写完整镜像地址并原样提交。
- 目标架构为空时使用本机运行时默认值；存在时只接受明确的操作系统和架构组合。
- 拉取已经存在的镜像、注册表返回相同摘要或标签指向新摘要时，必须以操作后的实际镜像回读为准。
- 容器名称大小写、点、短横线和下划线必须按单一规则校验；名称前导连字符、空白和 shell 元字符
  必须被拒绝。
- CPU 和内存为空表示使用运行时默认值；存在时必须为有限正值，不能接受负数、零或非数值。
- 端口映射在本功能中仅允许绑定本机回环地址；GUI 不以 root 运行，因此主机端口只允许
  `1024...65535`。容器端口仍允许 `1...65535`，例如 SSH 映射为 `2222:22/tcp`。端口越界、
  协议未知、重复主机端口或格式不完整必须在执行前拒绝。
- 环境变量采用一行一个 `KEY=value`；键重复、键非法或缺少等号必须拒绝。值可为空，但不得写入
  操作摘要、错误消息或页面回读。
- 进程参数采用一行一个参数；每行均作为独立值传递，不解释引号、变量、重定向或 shell 语法。
- 页面刷新、网络重试或重复点击不得重复拉取或创建；相同幂等键必须返回原操作，不同请求不得复用。
- 操作执行期间外部命令改变镜像或容器状态时，最终状态以最新权威回读为准。
- Docker Hub API 超时、限流或返回无效数据时，只影响远程搜索区域，不影响本机
  镜像、容器和操作状态；页面必须显示可重试的中文错误。
- 标签缺失、无标签或标签分页失败时不得退回并静默使用 `latest`；页面保留仓库结果并显示可重试错误。
- 拉取进度输出被拆分为多个数据块、包含无关行或偶发缺失时，不得导致拉取失败；没有可解析百分比时
  页面显示不确定进度，后续百分比不得倒退。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供镜像仓库快捷选择、镜像引用必填、目标架构可选的镜像拉取表单。
- **FR-002**: 系统必须在执行前校验镜像仓库、镜像引用和目标架构，并以逐字段中文错误拒绝无效输入。
- **FR-003**: 每次镜像拉取必须创建可追踪的异步操作，区分排队、执行、验证、成功和失败状态。
- **FR-004**: 镜像拉取只有在操作退出成功且权威镜像回读与请求匹配时才能标记成功。
- **FR-005**: 拉取成功回读必须包含规范化镜像名称、内容摘要、可用平台、大小和观测时间。
- **FR-006**: 系统必须提供容器名称和镜像必填的创建表单。
- **FR-007**: 创建表单必须支持可选 CPU、内存、多个端口映射、多个环境变量、多个进程参数和
  “创建后启动”选择。
- **FR-008**: 端口映射必须限定为本机回环地址；主机端口必须为 `1024...65535`，容器端口必须为
  `1...65535`。系统不得请求 root 权限，也不得通过本功能创建对全部网络接口开放的端口。
- **FR-009**: 创建前必须读取最新容器列表并拒绝同名目标；该检查不能替代创建后的独立回读。
- **FR-010**: 容器创建只有在操作退出成功且最新列表中出现同名目标时才能进入成功或可选启动阶段。
- **FR-011**: 勾选创建后启动时，系统必须先验证创建成功，再执行启动，并以最终运行状态作为成功依据。
- **FR-012**: 所有命令输入必须来自定义字段并作为独立参数传递；系统不得接受任意子命令、原始命令行
  或 shell 文本。
- **FR-013**: 每个写操作必须要求有效幂等键；重复提交相同请求返回原操作，不同请求复用键时拒绝。
- **FR-014**: 同一镜像或容器目标同时只能有一个进行中的写操作，且现有全局并发限制继续生效。
- **FR-015**: 操作记录必须提供安全请求摘要、开始和结束时间、退出状态、错误信息和权威回读，但不得
  包含环境变量值或注册表凭据。
- **FR-016**: 超时、取消、非零退出、输出无效、资源冲突和回读不匹配必须产生稳定的中文错误状态，
  且不得影响容器列表、详情、指标、启动、停止和日志功能。
- **FR-017**: 页面必须在操作进行时禁用对应重复提交，并在完成后自动刷新相关镜像或容器可见状态。
- **FR-018**: 表单、错误、进度和完成状态必须支持键盘操作并可由辅助技术读取，不能只依赖颜色。
- **FR-019**: 自动化测试必须使用固定输出和模拟执行器，不得真实拉取镜像、创建容器或启动容器。
- **FR-020**: 页面必须显示本机权威镜像列表，并允许创建表单从现有镜像名称中选择或填写镜像引用。
- **FR-021**: 镜像仓库快捷选择必须支持 Docker Hub，并保留通用完整镜像地址输入；页面只能把确定
  解析或原样校验后的完整镜像引用提交给现有受控 API，不得把仓库选择解释为额外 CLI 参数或 shell 文本。
- **FR-022**: 系统必须通过本机 Swift 服务提供 Docker Hub 公开仓库搜索和分页，不允许浏览器直接
  绕过服务端错误处理调用外部 API。
- **FR-023**: 系统不得提供 GHCR 专用搜索、命名空间浏览、快捷选择或 GitHub Token 配置；非 Docker Hub
  注册表只能通过完整镜像地址进入现有拉取流程。
- **FR-024**: 每个远程搜索结果必须包含可拉取的完整镜像引用、来源、名称和来源 API 提供的摘要信息，
  并能一键填入拉取表单；翻页不得自动触发镜像拉取。
- **FR-025**: 页面首次加载必须直接展示全部本机镜像且不对本机列表分页；远程搜索必须由用户输入触发，
  并允许逐页加载至来源 API 返回的全部匹配结果均已展示。
- **FR-026**: 用户打开远程仓库结果后，系统必须分页读取并展示该仓库的标签；只有用户明确选择标签后
  才能生成完整拉取引用，系统不得自动补充或默认提交 `latest`。
- **FR-027**: 镜像拉取必须使用 CLI `plain` 进度输出，将下载、解压和验证阶段及可解析的真实总百分比
  写入对应 Operation；页面必须以可访问进度条展示，且不得根据时间估算或伪造百分比。
- **FR-028**: 本机镜像区域必须默认展开，并在标题旁提供仅显示标准 chevron 图标的键盘可操作折叠按钮；
  展开时箭头向下、收起时箭头向右。按钮必须通过 `aria-controls` 关联内容、同步维护 `aria-expanded` 与
  “收起/展开本机镜像”无障碍名称，且拉取或创建操作提交时必须自动展开以显示状态。
- **FR-029**: 系统必须只允许删除已停止或已创建的精确容器目标；删除必须要求精确二次确认、有效幂等键，
  固定使用不含 `--all` 或 `--force` 的参数数组，并以最新列表中目标缺失作为唯一成功依据。

### Key Entities

- **镜像拉取请求**: 页面解析后的完整镜像引用、可选目标架构及幂等标识。
- **镜像回读**: 拉取后权威读取到的规范化名称、摘要、平台集合、大小和观测时间。
- **容器创建请求**: 目标名称、镜像、可选资源限制、端口、环境变量、进程参数和创建后启动选择。
- **资源操作**: 对某一镜像或容器目标执行的异步变更，包含安全摘要、生命周期状态、错误和最终回读。
- **镜像拉取进度**: CLI plain 输出解析出的阶段、单调总百分比、可选完成/总单元数和更新时间。
- **远程镜像搜索结果**: Docker Hub 公开仓库；只用于发现和填充拉取引用，不代表镜像已存在于本机。
- **远程镜像标签**: 属于单一搜索结果仓库的具体版本标识；选择后与仓库名称组合成可拉取的完整引用。
- **容器删除结果**: 精确目标的 CLI 退出状态、最新列表中的缺失回读及观测时间；不包含强制删除选项。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 60 秒内完成镜像拉取表单或常用容器创建表单的填写与提交。
- **SC-002**: 在固定验收样本中，100% 的无效输入在执行资源变更前被拒绝，并指出对应字段。
- **SC-003**: 100% 显示为成功的拉取和创建操作都包含与请求目标匹配的权威回读。
- **SC-004**: 操作请求被接受后 1 秒内出现可追踪状态，并在底层操作结束后 2 秒内显示最终结果。
- **SC-005**: 在包含秘密环境变量的全部验收场景中，响应、操作摘要、错误和页面均不出现秘密值。
- **SC-006**: 新功能失败时，现有容器状态、指标、详情、启停和日志验收场景保持 100% 可用。
- **SC-007**: 固定验收样本中的本机镜像必须 100% 在首页显示，不因远程搜索为空、失败或尚未开始而隐藏。
- **SC-008**: 对固定多页远程样本逐页加载后，100% 的匹配结果恰好显示一次，无遗漏或重复。
- **SC-009**: 对固定多页标签样本逐页加载后，100% 的标签恰好显示一次；未选择标签时产生的拉取请求数
  必须为零。
- **SC-010**: 固定流式进度样本中的每个有效更新必须在下一次 500ms Operation 轮询后显示；进度百分比
  不得倒退，验证阶段必须达到 100%。
- **SC-011**: 本机镜像区域连续收起和展开后，内容可见性、箭头方向、无障碍名称及 `aria-expanded` 必须 100% 一致；
  折叠期间的自动刷新不得产生重复镜像或写操作。
- **SC-012**: 固定验收样本中，100% 的运行中容器删除请求在 CLI 执行前被拒绝；100% 的删除成功状态
  都包含 `targetAbsent=true` 的权威回读。

## Assumptions

- 当前用户需要常用创建参数，不需要在首版暴露运行时的全部高级选项。
- 可选创建参数限定为 CPU、内存、回环端口映射、环境变量、进程参数和创建后启动。
- 挂载、卷、网络选择、DNS、能力、只读根文件系统、Rosetta、特权/虚拟化、入口点覆盖、镜像构建、
  镜像删除和注册表登录不在本功能范围内。
- 用户已有访问目标公开注册表或已配置私有注册表凭据；本功能不收集或保存凭据。
- 非 Docker Hub 注册表不提供专用搜索或快捷配置，用户可通过完整 OCI 镜像地址使用现有拉取流程。
- 镜像拉取和容器创建可能耗时较长，因此采用已有的可轮询操作状态；拉取展示 CLI 提供的阶段总进度，
  不扩展为逐层日志或自定义下载估算。
- 创建后启动默认关闭；用户明确勾选后才执行启动。
