# Feature Specification: root 公钥 SSH 登录

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "在 GUI 创建容器时直接设置 root 公钥，并使用 root 仅公钥登录。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 显式启用 root 公钥登录 (Priority: P1)

本机用户创建启用 SSH 的容器时，可以显式选择使用 root 登录，并直接提供 root 的 SSH 公钥，无需进入容器手工修改用户、授权文件或 SSH 配置。

**Why this priority**: 用户需要以最少步骤获得具有管理权限的开发容器，同时必须避免把 root 密码登录暴露出来。

**Independent Test**: 在创建表单启用 SSH 和 root 登录，提供有效公钥并创建容器；确认页面显示 `root@127.0.0.1` 连接命令，匹配的私钥可以登录，而密码认证被拒绝。

**Acceptance Scenarios**:

1. **Given** 用户已启用 SSH，**When** 勾选“使用 root 登录（仅公钥）”并提供有效公钥，**Then** 系统将该公钥授权给 root，并显示使用 root 的本机连接命令。
2. **Given** 用户选择 root 登录，**When** 创建并启动容器，**Then** root 只能通过匹配的私钥登录，密码、交互式认证和空密码均不可用。
3. **Given** 用户没有现成密钥，**When** 在 root 模式下使用浏览器生成密钥对，**Then** 公钥自动填入 root 配置，私钥仍只下载到浏览器所在机器且不上传。

---

### User Story 2 - 保持普通用户安全默认值 (Priority: P2)

不需要 root 权限的用户继续使用现有普通用户公钥登录流程；root 登录选项默认关闭，不会因升级而改变已有创建习惯。

**Why this priority**: root 登录是高权限例外，必须由用户明确选择，不能成为新的隐式默认值。

**Independent Test**: 打开创建表单但不勾选 root 登录，确认用户名字段和普通用户创建行为与现有版本一致，并且 root 登录继续被拒绝。

**Acceptance Scenarios**:

1. **Given** 用户启用 SSH 但未选择 root 登录，**When** 创建容器，**Then** 系统按填写的普通用户名配置公钥，并禁止 root 登录。
2. **Given** 用户先选择 root 登录后又取消，**When** 提交创建，**Then** 表单恢复先前普通用户名并按普通用户模式提交。
3. **Given** 用户未启用 SSH，**When** 查看创建表单，**Then** root 登录选项不可启用且不会影响普通端口或进程参数。

---

### User Story 3 - 重启后继续使用同一 root 连接 (Priority: P3)

用户停止并重新启动 root SSH 容器后，可以继续使用相同端口、root 用户和私钥连接，无需再次设置公钥。

**Why this priority**: 创建时的一键配置只有在日常启停中保持有效，才能真正替代重复的容器内手工操作。

**Independent Test**: 创建一个 root SSH 容器，记录连接命令并验证登录；停止并重新启动后，确认连接命令不变且服务就绪后同一私钥仍可登录。

**Acceptance Scenarios**:

1. **Given** root SSH 容器已配置成功，**When** 容器停止后再次启动，**Then** root 授权公钥和仅公钥安全策略自动恢复。
2. **Given** 页面或管理服务被刷新或重启，**When** 再次查看容器详情，**Then** 页面仍从容器当前配置显示 root 登录身份、端口和连接命令。

### Edge Cases

- root 模式关闭时直接把普通用户名填写为 `root`，提交必须被拒绝，并提示改用显式 root 选项。
- root 模式开启时，普通用户名输入不得与 root 身份同时生效；取消 root 模式后应恢复用户此前填写的普通用户名。
- 公钥为空、包含多行、算法不受支持或长度超限时，必须在真实容器变更前拒绝请求。
- root 模式仍受现有 SSH 端口范围、端口冲突和仅绑定 `127.0.0.1` 的限制。
- SSH 首次安装失败或端口尚未就绪时，不得把“容器运行中”显示成“SSH 可连接”。
- 镜像缺少 root 账户目录或权限文件时，初始化必须安全失败并保留可理解的错误与日志入口。
- 现有容器不会被后台自动修改；此选项只应用于之后通过创建表单新建的容器。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: SSH 快速配置区 MUST 提供默认关闭的“使用 root 登录（仅公钥）”选项，且只有启用 SSH 后才能选择。
- **FR-002**: 用户选择 root 模式时，系统 MUST 明确显示登录身份为 `root`，并停止接受普通用户名作为有效登录身份。
- **FR-003**: 用户取消 root 模式时，系统 MUST 恢复本次表单中此前填写的普通用户名。
- **FR-004**: root 模式 MUST 将用户提供或浏览器生成的公钥授权给 root 账户，且 MUST NOT 要求或设置 root 密码。
- **FR-005**: root 模式 MUST 允许 root 公钥登录，同时 MUST 禁用密码认证、键盘交互认证、挑战响应认证和空密码认证。
- **FR-006**: 普通用户模式 MUST 继续禁止 root 登录，并保持现有用户名、公钥和连接命令行为不变。
- **FR-007**: root 模式的 SSH 端口 MUST 只绑定 `127.0.0.1`，并继续使用现有 1024 至 65535 范围及端口冲突校验。
- **FR-008**: 创建成功后，容器详情 MUST 显示以 `root@127.0.0.1` 为目标且包含自定义端口的可复制连接命令。
- **FR-009**: 容器停止后再次启动时，系统 MUST 自动恢复 root 授权公钥、SSH 服务和仅公钥认证策略。
- **FR-010**: 页面刷新或管理服务重启后，系统 MUST 从容器当前配置重新派生 root 登录身份和连接信息，不得依赖浏览器内存或影子数据库。
- **FR-011**: 操作摘要、详情、日志和错误信息 MUST NOT 回显完整公钥；私钥 MUST NOT 上传、写入创建请求或由服务端保存。
- **FR-012**: 系统 MUST 在执行真实容器变更前拒绝无效公钥、非法端口以及普通模式下填写的 `root` 用户名。
- **FR-013**: 系统 MUST 提示 root 登录具有高权限，并明确说明密码登录保持禁用。
- **FR-014**: 该功能 MUST NOT 自动改写现有容器；已有容器需要重新创建才能使用此创建预设。
- **FR-015**: 未启用 SSH 时，现有创建容器、保持容器运行、环境变量和进程参数流程 MUST 保持不变。

### Key Entities

- **SSH 登录身份**: 某次创建请求选择的普通用户或显式 root 身份；决定授权公钥的目标账户和连接命令。
- **root SSH 配置**: root 登录所需的宿主机端口、公钥及仅公钥认证策略，不包含密码或私钥。
- **SSH 连接信息**: 从当前容器配置派生的本机地址、端口、登录身份和可复制命令。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 60 秒内通过创建表单完成 root 公钥 SSH 配置，无需手工进入容器或编写安装命令。
- **SC-002**: 100% 的 root 模式验收样本使用匹配私钥成功登录，同时密码、空密码和交互式认证全部被拒绝。
- **SC-003**: root 登录选项在 100% 的新表单中默认关闭；未选择该选项的普通用户创建回归样本行为不变。
- **SC-004**: 对 root SSH 容器执行一次停止和再次启动后，连接身份、端口和授权密钥 100% 保持不变，并在服务就绪后恢复连接。
- **SC-005**: 所有无效公钥、非法端口和隐式 root 用户名样本都在真实容器变更前被拒绝，并显示对应字段错误。
- **SC-006**: 所有 root SSH 监听仅可通过本机回环地址访问，远程网络接口上无新增监听。

## Assumptions

- 此功能延续现有 SSH 快速配置范围，仅用于通过 GUI 新建容器，不原地迁移已有容器。
- 用户接受 root 公钥登录的高权限风险，并通过一个默认关闭的显式选项表达授权。
- 服务端仍永远不接收或保存私钥；Termius 等客户端应导入浏览器下载的对应私钥。
- 首期支持范围与现有 SSH 快速配置一致；不支持的软件包管理环境会给出明确初始化失败信息。
- root 模式仍只服务于本机开发，不开放局域网或互联网访问。
