# Research: SSH 快速配置

## Decision 1: 使用结构化 SSH 预设，不暴露命令文本

**Decision**: 创建请求新增可选 SSH 对象，仅包含宿主机端口、用户名和公钥。浏览器不提交入口点、安装
命令、`sshd_config` 或 shell 文本；服务选择一个版本固定的初始化脚本，并把它作为独立进程参数交给 CLI。

**Rationale**: 用户目标是减少手工参数，同时项目宪章禁止浏览器提供任意命令。固定脚本可以离线审计和
精确测试；端口、用户名和公钥均以数据处理，不参与命令拼接。

**Alternatives considered**:

- 自动填充现有“进程参数”文本框：仍会把复杂 shell 暴露给用户，且容易把 `-lc` 误当可执行文件。
- 新增任意启动命令输入：扩大命令执行面并违反宪章。
- 只显示教程让用户进入容器配置：没有实现用户要求的 GUI 简化。

## Decision 2: 首次启动安装 OpenSSH，并让 sshd 成为主进程

**Decision**: 对 Debian/Ubuntu 系列镜像，固定脚本先检查 `/usr/sbin/sshd`；缺失时使用系统软件包管理器
安装。随后创建/更新指定非 root 用户的 `authorized_keys`，生成缺失的服务器主机密钥，写入只允许公钥
的独立配置片段，校验配置后 `exec /usr/sbin/sshd -D -e`。

**Rationale**: 主进程常驻可让容器状态直接反映 SSH 服务生命周期；每次容器启动都会执行同一幂等脚本，
已有软件、授权文件和主机密钥会继续复用，因此不需要守护进程或宿主机影子配置。

**Alternatives considered**:

- 容器启动后再执行安装命令：需要新的 exec 写操作、竞态和额外状态协调。
- 在 sshd 后运行 `sleep infinity`：服务失败时容器仍显示运行，降低可观察性。
- 为每种镜像维护脚本：首期范围不需要，失败时保留日志即可。

## Decision 3: 公钥通过保留环境变量传递并在回读时脱敏

**Decision**: 公钥和用户名通过两个保留环境变量作为独立参数进入容器；用户自定义环境变量不得占用这些
名称。公钥只用于写入 `authorized_keys`，不写入标签或操作安全摘要。详情 JSON 对环境数组中敏感变量的
值进行脱敏；安全摘要只保留端口、用户名、公钥类型和标准 SHA-256 指纹。

**Rationale**: CLI 1.3.1 创建命令没有安全的标准输入或秘密挂载选项；环境参数能保持数组边界且避免文本
插值。公钥不是私钥，但规格要求不完整回显，指纹足以帮助用户辨认。

**Alternatives considered**:

- 把公钥写进容器标签：列表与详情会直接公开完整内容且可能超过标签预期。
- 创建宿主机临时文件并挂载：引入文件生命周期、权限和清理风险。
- 页面上传私钥：不需要且安全风险不可接受。

## Decision 4: 容器标签保存可回读的非秘密 SSH 元数据

**Decision**: 创建时增加启用标记、宿主机端口和用户名三个固定标签。容器列表解析器只在启用标记正确、
端口处于 1024...65535、用户名通过相同规则时生成 SSH 元数据。连接地址永远固定为 `127.0.0.1`。

**Rationale**: 标签属于官方 CLI 返回的当前容器配置，页面刷新、GUI 重启和外部 CLI 操作后仍可重建连接
命令，同时不需要数据库。严格解析可避免损坏标签把状态端点变成任意端口探测器。

**Alternatives considered**:

- 只在浏览器内保存本次请求：刷新后丢失且形成不可靠状态。
- 增加本地配置数据库：会与 CLI 资源生命周期分叉。
- 从进程脚本或环境内容猜测：易漂移且可能泄露公钥。

## Decision 5: 读取 SSH 协议横幅判定就绪

**Decision**: `GET /containers/{id}/ssh` 先回读容器详情和受信标签；仅对运行中的已配置容器，以最长
750ms 连接其 `127.0.0.1` 宿主机端口并读取首行，只有以 `SSH-` 开头才返回 `ready`。运行但未收到横幅
返回 `initializing`；停止返回 `stopped`；容器错误返回 `failed`。

**Rationale**: `container start` 成功和容器运行都不能证明包安装完成或 sshd 正在监听。协议横幅比单纯
TCP connect 更能排除端口被其他服务占用，同时完全限制在回环地址与已验证标签端口。

**Alternatives considered**:

- 运行 `container exec` 检查进程：周期性执行容器进程属于额外变更且增加 CLI 负载。
- 只按容器状态显示就绪：会在首次安装阶段误报。
- 接受浏览器提供待探测端口：形成不必要的本机端口扫描接口。

## Decision 6: SSH 模式自动创建后启动并占用进程入口

**Decision**: 启用 SSH 时必须 `startAfterCreate=true`，且不允许同时提供自定义进程参数；普通端口和非保留
环境变量仍可并存。界面启用 SSH 后自动勾选并锁定“创建后启动”，清空并禁用进程参数区域。

**Rationale**: 初始化只有启动后才能发生；一个容器只能有一个主进程入口。显式拒绝冲突比静默忽略参数
更安全，自动启动也符合“一键可连接”的用户目标。

**Alternatives considered**:

- 允许创建后不启动：用户会误以为 SSH 已配置完成。
- 把用户进程作为 sshd 子进程：需要进程管理器和复杂生命周期，超出轻量范围。
- 静默覆盖用户参数：不可预测且难以诊断。

## Decision 7: 端口、用户名和公钥双端校验

**Decision**: 宿主机端口限定 1024...65535，并与普通映射的宿主机端口唯一；用户名限定为最多 32 位
的小写 Linux 安全名称且禁止 `root`；公钥限定单行、最多 4096 字符、受支持算法前缀和可解码的 Base64
主体。浏览器提供即时字段错误，服务端在任何 CLI 调用前重复校验。

**Rationale**: 客户端校验提高可用性，服务端校验才构成安全边界。窄用户名规则让连接命令和固定脚本无需
引号或转义。

**Alternatives considered**:

- 接受任意 Linux 用户名：不同发行版规则不一且增加脚本转义风险。
- 只检查公钥以 `ssh-` 开头：随机文本会进入容器后才失败。
- 自动选择随机端口：用户要求可自定义，且不可稳定显示重启后的命令。

## Decision 8: 自动化不创建真实 SSH 容器

**Decision**: CLI 形状、重启语义、标签回读、HTTP 状态和浏览器流程全部使用固定执行器、夹具和替换检查器
验证。真实验收只读取现有 CLI 版本、容器/镜像列表和页面资源；创建 SSH 容器需要用户对确切目标另行授权。

**Rationale**: “开始开发”授权代码修改，不等同于授权安装软件、占用端口或创建容器。模拟可以证明参数
和状态机且不触碰用户基础设施。

**Alternatives considered**:

- 自动创建并删除临时容器：仍会拉包、占用端口且删除可能失败。
- 跳过 CLI 形状测试只做页面检查：不能证明安全参数和重启行为。
