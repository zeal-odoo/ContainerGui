# Feature Specification: 容器 CPU 与内存指标

**Feature Branch**: `main`

**Created**: 2026-08-29

**Status**: Implemented and verified

**Input**: User description: "添加容器的CPU使用和内存使用率"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看容器资源使用情况 (Priority: P1)

作为本机容器管理员，我希望在容器概览和所选容器详情中看到当前 CPU 使用率与内存使用情况，
以便快速识别资源占用异常，而不必切换到终端执行额外命令。

**Why this priority**: 资源指标直接补足现有状态列表的诊断价值，是本需求的完整用户价值。

**Independent Test**: 使用包含运行中、已停止、首次采样、连续采样和统计失败的固定样本打开页面；
可以验证运行中容器显示资源指标、已停止容器不显示陈旧值，并且统计失败不影响列表与详情使用。

**Acceptance Scenarios**:

1. **Given** 一个运行中的容器已有连续资源样本，**When** 用户查看容器概览，**Then** 页面显示
   CPU 使用率、内存使用率以及内存已用量和上限。
2. **Given** 一个运行中的容器只有首个资源样本，**When** 用户查看页面，**Then** 内存指标立即显示，
   CPU 区域明确显示正在采样，不伪造百分比。
3. **Given** 一个已停止或已创建但未运行的容器，**When** 用户查看概览或详情，**Then** CPU 和内存
   指标显示为未运行或不可用，不沿用其先前运行时的数据。
4. **Given** 资源统计读取超时、失败或返回无效数据，**When** 页面刷新，**Then** 容器列表和详情仍可
   正常使用，指标区域显示独立的暂不可用状态。
5. **Given** 外部终端改变了容器负载，**When** 页面完成下一次可见状态刷新，**Then** 用户看到基于
   最新权威样本重新计算的指标。

### Edge Cases

- CPU 累计计数因容器重启、计数器复位或溢出而小于上一样本时，本轮 CPU 使用率不可用并重新采样。
- 多核容器的 CPU 使用率可以超过 100%；100% 表示一个核心被完全占用。
- 内存上限为零、缺失或小于当前用量时，不得除零或显示非有限数值；原始用量仍可安全展示。
- 统计结果包含列表中不存在的容器，或运行中容器在采样期间停止、删除时，只显示仍能与最新容器
  标识和状态匹配的结果。
- 某一容器的指标缺失不得阻止其他容器指标或基础列表渲染。
- 页面隐藏、请求被取消或连续刷新时，不得启动无界的并发统计任务。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须为每个运行中容器提供当前 CPU 使用率和内存使用率。
- **FR-002**: CPU 使用率必须使用“100% 等于一个完整核心”的口径，并允许多核负载超过 100%。
- **FR-003**: 内存指标必须同时包含当前使用量、限制值和由两者计算的百分比。
- **FR-004**: 容器概览必须提供可快速比较的 CPU 与内存指标；容器详情必须提供相同口径的完整值。
- **FR-005**: 首个样本不足以计算 CPU 使用率时，系统必须显示明确的采样中状态，不能显示零值。
- **FR-006**: 已停止、已创建、未知或异常状态的容器不得显示先前运行时的资源使用值。
- **FR-007**: 指标必须随现有可见页面刷新更新，并可追溯到最近一次权威资源样本。
- **FR-008**: 指标读取失败必须与容器状态读取隔离；失败不得清空或阻塞已经成功读取的列表和详情。
- **FR-009**: 系统不得持久化资源指标；仅可保留计算连续 CPU 样本所需的短期内存状态。
- **FR-010**: 指标状态必须通过文字和数值表达，不能仅依赖颜色，且必须可由辅助技术读取。
- **FR-011**: 统计输出缺少必需标识、包含非法负值或无法解析时，系统必须拒绝该次指标快照并显示
  安全的不可用状态。
- **FR-012**: CPU 和内存显示必须使用有限数值并采用一致的精度与容量单位，避免误导性小数。

### Key Entities

- **资源样本**: 某一容器在一个权威观测时间点的累计 CPU 时间、当前内存用量和内存上限。
- **资源使用情况**: 由当前样本及可选上一样本计算出的 CPU 百分比、内存百分比、显示状态和观测时间。
- **指标快照**: 一次刷新中多个运行中容器的资源使用情况集合；不包含已停止容器的陈旧样本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常本机环境中，95% 的运行中容器在页面打开后两个刷新周期内显示 CPU 与内存指标。
- **SC-002**: 在验收样本中，100% 的已停止或已重启容器不会显示上一次运行留下的资源数值。
- **SC-003**: 当资源统计读取失败时，100% 的基础容器列表和详情仍保持可用并显示独立错误状态。
- **SC-004**: 对已知样本进行验收时，CPU 与内存百分比计算误差不超过 0.01 个百分点。
- **SC-005**: 用户无需离开容器概览即可在 10 秒内判断哪个运行中容器占用最多 CPU 或内存。

## Assumptions

- 当前用户需要的是实时诊断指标，不需要历史曲线、告警阈值或长期存储。
- 资源指标只适用于运行中容器；其他状态显示明确的未运行或不可用状态。
- 页面继续使用现有五秒可见刷新周期；CPU 首次采样可等待下一个刷新周期。
- 容器运行时提供累计 CPU 时间、当前内存用量和内存上限，且容器标识可与现有列表精确匹配。
- 本功能不增加网络、磁盘 I/O、进程数、主机总资源或容器资源限制编辑能力。
