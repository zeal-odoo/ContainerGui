# Feature Specification: 容器存储容量

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: Implemented

**Input**: User description: "添加容器的容量的大小"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看运行中容器的存储容量 (Priority: P1)

本机用户在容器概览和详情中可以直接看到容器根文件系统的已用空间、总容量和使用率，不必进入容器手动查询。

**Why this priority**: 存储空间是判断容器是否接近磁盘上限以及排查写入失败的基础信息，与现有 CPU 和内存指标同等重要。

**Independent Test**: 使用一个返回确定容量数据的运行中容器，验证概览和详情显示相同的已用空间、总容量和使用率。

**Acceptance Scenarios**:

1. **Given** 一个运行中容器能返回有效的根文件系统容量，**When** 仪表板刷新，**Then** 容器行显示“使用率”和“已用 / 总容量”。
2. **Given** 用户打开同一运行中容器的详情，**When** 容量数据已读取，**Then** 详情显示与概览一致的根文件系统容量信息。
3. **Given** 容量值较大或不足一个 GiB，**When** 页面展示数值，**Then** 使用易读单位且不丢失已用与总容量的区别。

---

### User Story 2 - 明确容量不可读取的状态 (Priority: P2)

本机用户在容器未运行或容量查询失败时能看到明确状态，不会把未知容量误认为零容量或已满。

**Why this priority**: 错误的零值或百分比会误导容量判断；单个容器不支持查询时也不应影响其他容器状态。

**Independent Test**: 分别模拟停止容器、查询失败和格式异常，确认页面显示“未运行”或“暂不可用”，同时其他有效容器仍正常显示。

**Acceptance Scenarios**:

1. **Given** 一个已停止或尚未运行的容器，**When** 仪表板刷新，**Then** 容量显示“未运行”。
2. **Given** 一个运行中容器无法返回有效容量，**When** 仪表板刷新，**Then** 该容器显示“暂不可用”且不展示伪造的零值。
3. **Given** 多个运行中容器中只有一个容量查询失败，**When** 刷新完成，**Then** 其他容器的容量仍正常显示。

### Edge Cases

- 容量总值为零、已用值大于总值、负数、溢出或输出格式不完整时，必须视为不可用。
- 容器在容量读取期间停止或消失时，只影响该容器的容量结果，不影响列表及其他指标。
- 容器镜像没有标准容量查询工具时，页面必须显示暂不可用。
- 页面第一次加载、自动刷新尚未完成或上一轮数据已失效时，必须显示读取中而不是沿用错误状态。
- 总容量是根文件系统可见容量，不应与镜像下载大小、宿主机目录大小、挂载卷大小或磁盘配额混淆。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每个运行中容器读取根文件系统的已用字节数、总容量字节数和可用字节数。
- **FR-002**: 容器概览 MUST 新增“存储”信息，并同时展示使用率以及“已用 / 总容量”。
- **FR-003**: 容器详情 MUST 展示与概览同一读取周期的根文件系统容量信息。
- **FR-004**: 已停止或尚未运行的容器 MUST 显示“未运行”，不得显示零容量。
- **FR-005**: 单个运行中容器容量读取失败时 MUST 显示“暂不可用”，且不得使容器列表、CPU、内存或其他容器容量读取整体失败。
- **FR-006**: 系统 MUST 拒绝总容量为零、数值溢出、负数、已用值大于总值或格式不完整的容量结果。
- **FR-007**: 容量读取 MUST 是只读行为，不得修改容器文件、生命周期或配置。
- **FR-008**: 容量数据 MUST 随现有资源指标自动刷新，且活动中的上一轮刷新不得堆积重复查询。
- **FR-009**: 页面 MUST 使用现有易读字节单位格式，并清楚标注显示的是根文件系统，而不是镜像大小或挂载目录容量。
- **FR-010**: 此功能 MUST 保持现有容器列表、详情、CPU、内存、网络地址和控制操作兼容。
- **FR-011**: 自动化验证 MUST 使用固定输出和可替换的命令边界，不得修改用户的真实容器。

### Key Entities

- **容器根文件系统容量**: 某个运行中容器在一次读取时点的已用字节、可用字节、总容量、使用率和可用状态。
- **容量展示状态**: 读取中、可用、暂不可用或未运行，用于防止未知值被误解为零值。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 返回有效容量的运行中容器都在一个自动刷新周期内显示已用空间、总容量和使用率。
- **SC-002**: 概览和详情对同一容器展示的容量数值在同一读取周期内完全一致。
- **SC-003**: 100% 的停止、查询失败和无效输出场景分别显示“未运行”或“暂不可用”，不显示伪造的零容量。
- **SC-004**: 一个容器的容量读取失败不会阻止其他容器及现有 CPU、内存信息显示。
- **SC-005**: 用户无需执行容器命令即可在一次查看中辨认根文件系统已用空间和总容量。

## Assumptions

- “容器容量”解释为容器根文件系统当前的已用空间和可见总容量，而不是镜像下载大小、挂载卷容量或宿主机目录大小。
- 本次只增加只读展示，不增加创建容器时的磁盘配额设置，也不改变现有容器磁盘大小。
- 停止容器无法执行实时容量读取，因此显示“未运行”；不通过缓存猜测停止前容量。
- 容量是运行时可见值，稀疏磁盘或共享存储可能使其与宿主机实际占用空间不同，界面会使用“根文件系统”措辞避免误解。

- 2026-08-30：测试先行的定向编译按预期因缺少容量模型、解析器与 API 字段失败；实现后 20 个容量相关 Swift 测试全部通过。
- 2026-08-30：完整 Swift 测试执行 164 个测试，0 失败；其中 2 个需显式开启的外部只读检查按设计跳过。
- 2026-08-30：Node 前端测试 6/6 通过，覆盖正常容量与“未运行 / 读取中 / 暂不可用”展示。
- 2026-08-30：显式开启的 Apple container 只读集成检查 1/1 通过；未执行容器生命周期或配置修改。
- 2026-08-30：运行态 API 回读 GUI `2.10.0`，3 个运行中容器均返回 `rootFilesystem.state=ready` 与合法字节值。
- 2026-08-30：浏览器确认概览显示“存储”列，`odoo19` 详情显示“根文件系统 0.47% · 2.38 GiB / 503.95 GiB”，页面无控制台警告或错误。
