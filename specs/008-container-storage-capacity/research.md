# Phase 0 Research: 容器存储容量

## 1. 容量语义与权威读取

**Decision**: “容器容量”定义为运行中容器根文件系统 `/` 的已用、可用和总字节数；使用固定参数 `container exec <id> df -kP /` 读取。

**Rationale**:

- 本机 Apple Container CLI 1.3.1 的 `stats` 只返回累计块读写字节，不提供磁盘容量；这些 I/O 计数不能当作容量。
- `container inspect` 的资源配置包含 CPU 和内存，但没有磁盘容量字段。
- 在三个当前运行中容器上验证 `df -kP /` 均返回 POSIX 单行格式，并给出根文件系统的 1024 字节块总数、已用量和可用量。
- 固定参数数组不使用 shell，也不允许浏览器输入任意命令；查询不写入容器文件或改变生命周期。

**Alternatives considered**:

- 使用 `blockReadBytes + blockWriteBytes`：拒绝；这是累计 I/O 流量，不是已用空间或容量。
- 使用镜像大小：拒绝；镜像下载大小不等于容器根文件系统容量或可写层用量。
- 导出容器文件系统后统计：拒绝；开销大、读取时间长，并会引入大量临时数据。
- 读取宿主机内部稀疏磁盘文件：拒绝；依赖未公开内部布局，且不能代表容器可见容量。

## 2. 解析与数值口径

**Decision**: 只解析 `-kP` 的最后一个非空数据行，将第 2、3、4 列分别作为 1024 字节块的总量、已用量和可用量，使用溢出检查换算成字节；使用率由 `已用 / 总量 × 100` 计算。

**Rationale**:

- POSIX 格式使每个文件系统占一行；解析数字列不依赖本地化表头。
- 重新按精确字节值计算可展示小数百分比，不受命令输出整数百分比的向上取整影响。
- 总量必须大于零，且已用与可用不得大于总量；任何缺列、非数字、负数或乘法溢出都拒绝。

## 3. 失败隔离和并发

**Decision**: 先取得现有资源指标快照，再并行读取其中每个运行中容器的根文件系统；每个容量读取独立降级为 `unavailable`，不让单项失败使整个指标端点失败。

**Rationale**:

- 极简镜像可能没有 `df`，容器也可能在读取期间停止或被删除。
- 并行执行避免容器数量线性放大整体延迟，并保持现有五秒端点上限。
- 页面已有防重叠刷新门禁；无需为本次功能引入持久缓存或新的调度器。

## 4. API 与界面集成

**Decision**: 在现有 `GET /api/v1/containers/metrics` 每个条目中增加 `rootFilesystem` 对象；概览增加“存储”列，详情增加“根文件系统”事实项。

**Rationale**:

- CPU、内存和容量拥有相同的刷新周期和容器 ID，扩展现有快照比新增端点更简单且避免额外轮询。
- `rootFilesystem.state` 明确区分 `ready` 与 `unavailable`；停止状态仍由权威容器列表判断为“未运行”。
- UI 复用现有百分比、字节格式和主次两行指标样式。

## 5. 容量解释边界

**Decision**: 界面使用“存储”和“根文件系统”措辞，并显示“已用 / 总容量”；不宣称总容量等于宿主机实际占用或独立配额。

**Rationale**:

- 当前三个容器均看到约 504 GiB 的根文件系统总量，但实际已用量随镜像和容器内容不同。
- 稀疏磁盘、共享存储和文件系统预留空间会使容器可见容量与宿主机实际占用不同。
- 挂载目录或卷拥有独立语义，应作为后续独立功能处理。

## Evidence

- 本机 `container` CLI 1.3.1：`container stats --no-stream --format json`、`container inspect odoo19`、`container exec <id> df -kP /` 的只读回读（2026-08-30）。
