# Feature Specification: Odoo 与通用共享目录

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: Implemented

**Input**: User description: "创建容器时，所有镜像都能映射本机目录；Odoo 镜像把该目录作为自定义模块目录，并且只对 Odoo 显示数据库地址和端口配置。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 为任意容器共享本机目录 (Priority: P1)

本机用户创建任意镜像的容器时，可以填写一个现有本机目录和容器内目录，将其作为可读写的文件交换目录，无需手工编写挂载参数。

**Why this priority**: 本机与容器交换文件是所有镜像都需要的基础能力，也是 Odoo 自定义模块挂载的共同底座。

**Independent Test**: 使用非 Odoo 镜像填写一个临时本机目录和容器目录并创建；确认创建请求包含唯一的读写目录映射，未填写时原有创建流程保持不变。

**Acceptance Scenarios**:

1. **Given** 用户选择非 Odoo 镜像，**When** 填写现有本机绝对目录并保留默认容器目录 `/workspace`，**Then** 系统以读写方式映射该目录，并把它说明为本机与容器之间的文件交换目录。
2. **Given** 用户选择非 Odoo 镜像，**When** 修改为另一个有效的容器绝对目录，**Then** 系统使用用户指定的目标目录创建挂载。
3. **Given** 用户不填写本机目录，**When** 创建容器，**Then** 系统不创建目录映射，其他 CPU、内存、端口、SSH、环境变量和进程参数行为不变。

---

### User Story 2 - Odoo 自定义模块目录预设 (Priority: P1)

用户选择 Docker Hub 官方 Odoo 镜像时，创建表单自动把本机共享目录解释为 Odoo 自定义模块目录，并将容器目标固定为 `/mnt/extra-addons`。

**Why this priority**: Odoo 开发的主要目标是让本机模块修改立即对容器可见；固定官方约定目录可以消除重复输入和路径错误。

**Independent Test**: 分别选择 `odoo:19.0`、完整官方 Odoo 镜像引用和一个名称中仅包含 `odoo` 的非官方镜像；确认只有前两者显示 Odoo 预设，且目标目录不可改为其他值。

**Acceptance Scenarios**:

1. **Given** 用户选择 Docker Hub 官方 Odoo 镜像，**When** 打开或切换到创建表单，**Then** 共享目录标题变为“Odoo 自定义模块目录”，容器目标显示且固定为 `/mnt/extra-addons`。
2. **Given** 用户从 Odoo 镜像切换为其他镜像，**When** 继续填写表单，**Then** 目录说明恢复为通用文件交换，容器目标恢复为可编辑的通用默认值。
3. **Given** 镜像名称只是包含 `odoo` 字样但不是 Docker Hub 官方 Odoo 仓库，**When** 打开创建表单，**Then** 系统按普通镜像处理，不显示 Odoo 专属配置。

---

### User Story 3 - 仅为 Odoo 配置数据库端点 (Priority: P2)

用户选择 Docker Hub 官方 Odoo 镜像时，可以在 GUI 中填写数据库地址和端口；选择其他镜像时，这两个字段完全隐藏且不能通过请求绕过界面提交。

**Why this priority**: Odoo 启动依赖数据库连接，结构化字段比手工环境变量更简单，也能防止非 Odoo 容器收到无关配置。

**Independent Test**: 选择官方 Odoo 镜像，修改数据库地址和端口并提交，确认两项配置生效；再选择非 Odoo 镜像并构造包含 Odoo 数据库配置的请求，确认在真实容器变更前被拒绝。

**Acceptance Scenarios**:

1. **Given** 用户选择官方 Odoo 镜像，**When** 查看创建表单，**Then** 页面显示数据库地址和端口，默认值分别为 `db` 和 `5432`，并允许用户修改。
2. **Given** 用户填写有效数据库地址和端口，**When** 创建 Odoo 容器，**Then** 容器启动配置使用对应地址和端口。
3. **Given** 用户选择非 Odoo 镜像，**When** 查看创建表单或提交伪造请求，**Then** 页面不显示数据库配置，服务端也拒绝 Odoo 专属字段。

### Edge Cases

- 本机目录为空时不创建挂载；只填写容器目录不得隐式创建挂载。
- 本机目录不是绝对路径、不存在、不是目录，或指向文件时，必须在执行容器创建前拒绝。
- 本机目录或容器目录为根目录、包含换行、空字节、逗号或相对路径段时，必须拒绝，避免扩大映射范围或破坏挂载参数。
- 非 Odoo 容器目标不是绝对路径或为空时，必须在创建前提示对应字段。
- Odoo 容器目标被客户端篡改时，服务端必须拒绝或规范回 `/mnt/extra-addons`，不得挂载到任意目标。
- 数据库地址为空、包含空白或 URL 路径，或者端口不在 1 至 65535 范围内时，必须在创建前拒绝。
- 结构化 Odoo 数据库配置与普通环境变量中的 `HOST` 或 `PORT` 重复时，必须拒绝并提示只保留一种配置方式。
- 页面刷新、镜像列表刷新或创建失败后重新打开表单时，镜像类型对应的字段可见性和默认值必须一致。
- CLI 超时、非零退出或挂载失败时，页面不得显示容器创建成功，并应保留可操作的错误摘要。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 创建表单 MUST 为所有镜像提供一个可选的本机共享目录字段和容器目标目录字段。
- **FR-002**: 本机共享目录 MUST 使用用户明确填写的现有绝对目录；系统 MUST NOT 自动创建、猜测或扫描目录。
- **FR-003**: 共享目录 MUST 以读写方式挂载，并且每次创建请求首期最多接受一个共享目录。
- **FR-004**: 非 Odoo 镜像的容器目标 MUST 默认为 `/workspace`，并允许用户改为其他安全的绝对目录。
- **FR-005**: 系统 MUST 只把 Docker Hub 官方 Odoo 仓库的短引用或规范完整引用识别为 Odoo 镜像，不得根据任意子串判断。
- **FR-006**: 官方 Odoo 镜像的共享目录 MUST 标记为“Odoo 自定义模块目录”，容器目标 MUST 固定为 `/mnt/extra-addons`。
- **FR-007**: 官方 Odoo 镜像 MUST 显示数据库地址和端口字段，默认值分别为 `db` 和 `5432`；非 Odoo 镜像 MUST 隐藏这些字段。
- **FR-008**: 服务端 MUST 对镜像类型、共享目录和 Odoo 数据库字段重新校验，不能依赖浏览器字段隐藏或只读状态。
- **FR-009**: 数据库地址 MUST 接受有效主机名、IPv4 或 IPv6 地址，端口 MUST 为 1 至 65535 的整数。
- **FR-010**: Odoo 数据库地址和端口 MUST 作为该镜像支持的连接配置传递，且 MUST NOT 记录或返回用户的数据库密码。
- **FR-011**: 同一 Odoo 创建请求 MUST NOT 同时通过结构化字段和普通环境变量重复定义数据库地址或端口。
- **FR-012**: 本机目录未填写时，系统 MUST 忽略容器目录默认值并保持原有无挂载创建行为。
- **FR-013**: 系统 MUST 在执行真实创建前拒绝不存在的本机目录、文件路径、危险根目录和无效目标路径。
- **FR-014**: 创建失败、超时或状态回读不一致时，系统 MUST 显示失败，不得把请求提交或进程退出单独当作成功。
- **FR-015**: 此更新 MUST 保持现有 SSH、root 公钥、保持运行、CPU、内存、端口、环境变量和进程参数功能兼容。
- **FR-016**: 页面 MUST 用简短说明明确区分“Odoo 自定义模块目录”和“通用文件交换目录”的用途。

### Key Entities

- **共享目录配置**: 一个可选的本机绝对目录、容器绝对目标目录和固定的读写模式；属于单次容器创建请求。
- **镜像类别**: 根据选中的镜像引用派生的“官方 Odoo”或“普通镜像”类别；决定表单与服务端允许的专属字段。
- **Odoo 数据库端点**: 官方 Odoo 容器使用的数据库地址与端口，不包含数据库密码。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 60 秒内为任意新容器配置一个本机共享目录，无需手工编写挂载命令。
- **SC-002**: 100% 的官方 Odoo 镜像样本将自定义模块目录固定到 `/mnt/extra-addons`，100% 的非官方相似名称样本保持通用目录行为。
- **SC-003**: 数据库地址和端口只在 100% 的官方 Odoo 镜像表单中可见，所有非 Odoo 伪造请求均在真实创建前被拒绝。
- **SC-004**: 所有无效、缺失、危险或不存在的路径样本以及非法端口样本均在真实创建前被拒绝，并显示可理解的字段错误。
- **SC-005**: 未填写共享目录的现有创建回归样本全部保持原有行为，现有自动化测试全部通过。

## Assumptions

- 首期每个容器只配置一个本机共享目录；多目录、只读切换和高级卷管理不在本次范围。
- 用户通过文本框填写 macOS 上的绝对目录路径；浏览器不会承诺通过文件选择器获得可供服务端使用的完整目录路径。
- Odoo 识别范围只覆盖 Docker Hub 官方 `odoo` 仓库；第三方定制 Odoo 镜像先按普通镜像处理。
- Odoo 官方镜像使用 `/mnt/extra-addons` 作为自定义模块目录，数据库连接使用地址与端口；数据库用户和密码仍可沿用现有环境变量输入，本次不新增凭据字段。
- 本次能力只应用于新建容器，不自动修改或重建已有容器。
