# Feature Specification: Apple Container Web GUI

**Feature Branch**: `main`

**Created**: 2026-08-29

**Status**: Ready for Planning

**Input**: User description: "我现在用了苹果的 container，但它只是 CLI，用起来并不方便。我要做一个轻量级 GUI，方便管理 container，想用 Swift 编写，最好使用现有 Swift 框架，并采用 B/S 架构。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼看清运行状态 (Priority: P1)

作为在 Mac 上运行容器的单一用户，我希望打开浏览器后立即看到容器服务是否可用、所有现有
容器及其当前状态，并能查看单个容器的详细信息，从而不需要记忆和重复输入查询命令。

**Why this priority**: 状态可见性是后续所有管理动作的前提；即使只交付这一故事，产品也已经
能替代最高频的只读 CLI 查询。

**Independent Test**: 准备包含运行中、已停止和零容器三种状态的受控数据，用户仅通过页面即可
判断服务状态、定位一个容器并打开详情，且页面内容与同一时点的权威状态一致。

**Acceptance Scenarios**:

1. **Given** 容器服务可用且存在多个不同状态的容器，**When** 用户打开首页，**Then** 页面展示
   服务健康状态、容器总数及每个容器的标识、镜像、运行状态和可用网络地址。
2. **Given** 用户正在查看容器列表，**When** 用户选择一个容器，**Then** 页面展示该容器的完整
   可读详情，同时保留原始详情视图以便诊断。
3. **Given** 外部终端改变了容器状态，**When** 用户手动刷新或页面到达下一次刷新时点，**Then**
   页面展示最新状态且不保留冲突的旧状态。
4. **Given** 当前没有容器，**When** 用户打开首页，**Then** 页面明确展示空状态和可执行的下一步，
   而不是空白表格或通用错误。
5. **Given** 管理工具不可用或系统服务未运行，**When** 用户打开首页，**Then** 页面区分“工具未安装”、
   “版本不受支持”和“服务未启动”，并给出对应的安全处理提示。

### User Story 2 - 控制现有容器并查看日志 (Priority: P2)

作为用户，我希望从容器详情页启动已停止容器、正常停止运行中容器，并查看最近日志或持续日志，
从而完成日常排错和启停操作而无需切换到终端。

**Why this priority**: 启动、停止和日志是容器日常管理中最常用的写操作与诊断动作，且范围足够
小，可形成安全、完整的管理闭环。

**Independent Test**: 使用一个可重复启动和停止的测试容器，验证用户能只通过页面完成启动、
查看日志、停止三个动作；每个动作结束后页面必须显示重新读取的真实状态。

**Acceptance Scenarios**:

1. **Given** 一个已停止容器，**When** 用户点击启动，**Then** 页面显示进行中状态，动作结束后重新
   读取并展示运行中状态。
2. **Given** 一个运行中容器，**When** 用户请求正常停止并确认目标，**Then** 页面防止重复提交，
   完成后重新读取并展示已停止状态。
3. **Given** 一个产生标准输出的容器，**When** 用户打开日志，**Then** 页面先显示指定数量的最近日志，
   并允许用户开始和停止持续跟随。
4. **Given** 日志连接中断，**When** 页面检测到断开，**Then** 已显示日志仍然保留，页面明确标记
   已断开，并允许用户主动重新连接。
5. **Given** 操作过程中目标容器已被外部命令删除或改变状态，**When** 操作返回，**Then** 页面展示
   最新事实状态和可理解的冲突说明，不把请求已发送误报为操作成功。

### User Story 3 - 安全创建和删除容器 (Priority: P3)

作为用户，我希望通过受约束的表单运行一个新容器，并在不再需要时安全删除已停止容器，从而
覆盖基本生命周期管理而无需手写长命令。

**Why this priority**: 创建表单能显著减少参数输入错误，但涉及镜像下载、端口、挂载和环境变量，
需要在只读和现有容器控制稳定后再交付。

**Independent Test**: 使用一个已知测试镜像，用户只通过表单创建容器、观察其状态、停止容器并
删除它；最终权威列表中不再出现该容器，且其他容器未受影响。

**Acceptance Scenarios**:

1. **Given** 用户提供有效镜像引用，**When** 用户提交最小创建表单，**Then** 系统运行容器并在列表
   中展示最终标识和状态。
2. **Given** 用户需要自定义运行方式，**When** 用户填写名称、端口映射、环境变量、挂载、CPU 或
   内存限制，**Then** 系统先展示规范化后的配置摘要，再执行一次创建请求。
3. **Given** 表单包含无效端口、重复名称、无效挂载或不完整环境变量，**When** 用户提交，**Then**
   页面在能本地判断时阻止请求，并在外部校验失败时准确展示失败原因。
4. **Given** 一个已停止容器，**When** 用户点击删除，**Then** 页面展示容器名称和完整标识并要求
   二次确认，确认后删除并重新读取列表。
5. **Given** 一个仍在运行的容器，**When** 用户请求删除，**Then** 系统拒绝直接强制删除并引导用户
   先正常停止；MVP 不把停止和强制删除合并为一个隐式动作。

---

### User Story 4 - 恢复容器系统服务 (Priority: P4)

作为用户，我希望在容器系统服务未运行时从页面发起明确的启动操作，并看到启动进度与最终健康
状态，从而避免为了恢复服务仍需打开终端。

**Why this priority**: 这能补齐 GUI 的自恢复体验，但可能包含内核安装等机器级变更，因此必须在
基本容器管理和安全确认机制稳定后实现。

**Independent Test**: 在隔离的测试环境将系统服务置为未运行状态，用户通过页面发起启动并看到
最终健康回读；若缺少必要组件，页面先说明影响并等待明确确认。

**Acceptance Scenarios**:

1. **Given** 系统服务已停止且所需组件完整，**When** 用户确认启动，**Then** 页面展示进度并在服务
   健康后显示可用状态。
2. **Given** 启动需要下载或安装系统组件，**When** 用户请求启动，**Then** 页面在任何下载或安装前
   说明影响、大小或未知信息，并要求单独确认。
3. **Given** 启动命令结束但健康检查仍失败，**When** 页面完成回读，**Then** 操作显示失败并提供
   可用于诊断的错误摘要，不显示虚假的绿色成功状态。

### Edge Cases

- 管理工具路径存在但不可执行、版本文本无法识别，或客户端与后台服务版本不一致。
- 系统服务状态查询以非零状态结束，但输出仍包含可识别的“未注册/未运行”状态。
- 容器列表或详情返回未知字段、缺少必需字段、非 JSON 内容或超大输出。
- 查询或变更命令超时、被用户取消、进程异常退出，或仅有标准错误而没有标准输出。
- 同一容器动作被快速重复点击，或两个浏览器标签同时提交冲突操作。
- 操作退出成功，但目标状态未改变；操作退出失败，但外部并发操作已使目标达到期望状态。
- 日志持续增长、包含非 UTF-8 字节、单行极长、连接中断，或用户离开页面后后台进程仍在运行。
- 镜像拉取失败、端口已占用、挂载源不存在、目标名称在提交后被其他进程占用。
- 用户刷新确认页面、浏览器重发请求或返回上一页时，危险操作不得自动再次执行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在首页区分并展示管理工具安装状态、可识别版本、系统服务健康状态和最后
  刷新时间。
- **FR-002**: 系统必须列出运行中和已停止的全部容器，并为每个容器展示稳定标识、显示名称、镜像、
  当前状态以及可用网络地址。
- **FR-003**: 用户必须能手动刷新；系统也必须定期刷新非交互状态，并以最新权威读取结果替换旧结果。
- **FR-004**: 用户必须能查看单个容器的可读详情和未被重新解释的原始详情；敏感值必须被遮蔽。
- **FR-005**: 用户必须能启动已停止容器和正常停止运行中容器；页面只能展示与当前状态合法的动作。
- **FR-006**: 用户必须能查看可配置数量的最近日志，并主动开始、停止和重新连接持续日志。
- **FR-007**: 系统必须使用受约束表单创建容器，至少支持镜像引用，并可选支持名称、端口映射、
  环境变量、挂载、CPU 和内存限制。
- **FR-008**: 系统必须在提交创建请求前校验所有可本地判断的字段，并展示将被应用的规范化配置摘要。
- **FR-009**: 用户必须能删除已停止容器；MVP 必须拒绝直接强制删除运行中容器。
- **FR-010**: 删除、停止系统服务、安装组件以及其他可能丢失数据或影响全部容器的动作，必须展示
  解析后的具体目标和影响并要求二次确认。
- **FR-011**: 每个变更操作必须具有唯一操作标识，并展示等待、运行、成功、失败或取消状态；同一目标
  上的冲突操作不得并发执行。
- **FR-012**: 变更操作的最终成功必须同时满足请求进程结束和独立状态回读符合预期；部分成功必须
  逐项展示，不得汇总为整体成功。
- **FR-013**: 系统必须将用户可修正的输入错误、工具未安装、服务未运行、版本不兼容、超时、命令
  失败、输出无法解析和状态冲突显示为不同的可理解错误。
- **FR-014**: 系统必须支持从未运行状态启动容器系统服务；涉及下载或安装系统组件时必须在执行前
  取得单独确认。
- **FR-015**: 页面刷新、浏览器重试或重复点击不得自动重复执行非幂等变更。
- **FR-016**: 系统不得向用户提供任意命令、任意子命令或原始 shell 文本执行入口。
- **FR-017**: 系统不得持久化容器状态副本；页面展示状态必须可追溯到最近一次权威读取。
- **FR-018**: 环境变量值、认证信息和其他秘密不得出现在操作记录、错误摘要或后续页面回显中。
- **FR-019**: MVP 必须仅接受当前 Mac 本机浏览器连接；远程或局域网访问不属于本功能范围。
- **FR-020**: 页面必须提供中文界面，所有关键动作可通过键盘完成，并具有可区分的加载、空、成功、
  失败和断开状态。

### Key Entities

- **Container**: 由权威工具管理的单个容器；具有稳定标识、可选显示名称、镜像引用、运行状态、
  网络地址、创建配置和详情。其状态可在外部被改变。
- **System Health**: 当前机器上管理工具和后台服务的可用性快照；包含工具状态、版本、服务状态、
  读取时间和诊断摘要。
- **Run Configuration**: 用户在创建前确认的一次性配置；包含镜像、名称以及可选端口、环境变量、
  挂载和资源限制。秘密值只在本次操作中使用，不形成可回显记录。
- **Operation**: 一次受控的查询或变更；包含唯一标识、动作类型、目标、阶段、开始/结束时间、结果
  摘要和状态回读结果。
- **Log Session**: 针对一个容器的有界日志查看会话；包含目标、尾部行数、连接状态和用户主动停止
  信号，不代表容器的持久数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对包含 20 个容器的常见环境，用户从打开页面到准确指出系统健康状态和任意容器状态
  的时间不超过 10 秒。
- **SC-002**: 在本机正常运行条件下，95% 的列表刷新和详情打开在 2 秒内向用户呈现完整结果。
- **SC-003**: 启动或停止请求完成后，95% 的成功状态在权威状态实际改变后的 5 秒内反映到页面；
  其余情况必须显示等待或明确失败，而非错误成功。
- **SC-004**: 在验收测试中，100% 的删除和机器级变更都需要针对具体目标的二次确认，页面刷新、
  重试和重复点击造成的重复危险操作次数为 0。
- **SC-005**: 新用户在不查阅命令行帮助的情况下，能在 2 分钟内完成“定位容器、查看详情、查看日志”
  三项任务，首次完成率达到 90%。
- **SC-006**: 对工具缺失、服务停止、超时、非零退出、无法解析输出和状态冲突六类故障，验收样本
  中 100% 显示可区分且可采取下一步的错误信息。
- **SC-007**: 在用户通过终端改变容器状态后，一次手动刷新即可使页面与权威状态一致，验收中不得
  出现持久分叉状态。
- **SC-008**: 用户完成 P1 和 P2 的全部日常任务时不需要打开终端或手写命令。

## Assumptions

- 第一版面向一台 Apple Silicon Mac 的单一登录用户；B/S 指本机服务加本机浏览器，不表示局域网
  或互联网远程管理。若后续需要远程访问，必须作为包含认证、授权和传输保护的独立功能设计。
- 用户已按官方方式安装受支持的 Apple 容器管理工具；本产品不负责首次完整安装或升级该工具。
- 管理工具及其后台服务是容器状态的唯一权威来源；用户仍可能同时从终端执行操作。
- 第一版仅管理容器本身及系统健康。镜像构建/推送、注册表登录、镜像/卷/网络完整生命周期、机器、
  Kubernetes、交互式终端、文件复制、导入导出和编排不在当前范围。
- 创建表单只覆盖明确列出的常用参数；未覆盖的高级参数继续由用户通过官方命令行使用。
- 页面不长期保存业务数据或秘密；关闭服务后，只保留运行所需的非敏感设置和有限诊断记录。
- 自动化验收使用模拟或隔离资源；未经用户明确授权，不对现有真实容器执行写操作。
